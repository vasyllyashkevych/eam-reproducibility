# eam-reproducibility

Code, data and expected outputs for the IJITCS manuscript **PAPER021433**
*“Evolution-Aware Monitoring for Evolving Information Systems: Multidimensional Drift Assessment with a Version-Dependent Reference Model”* (V. Lyashkevych).

Repository: https://github.com/vasyllyashkevych/eam-reproducibility

## What can be reproduced

| Study | What it checks | How to reproduce | Database needed |
|---|---|---|---|
| A — controlled drift injection (RQ1) | evolution-state classification, Tables 5–6, Fig. 4 | `bash run_all.sh` | no |
| A — supplementary leave-one-dimension-out (LOFO) | contribution of each of the nine drift dimensions to the Study A macro-F1 (supplementary, not a manuscript table) | `bash run_all.sh` or `python3 code/study_a_lofo.py` | no |
| Joint ablation (RQ1, RQ2) | release-change vs runtime profile, Table 9 | `bash run_all.sh` | no |
| C — security drift of five libraries (RQ3) | advisory-based exposure, Fig. 6 | `bash run_all.sh` (frozen OSV cache) | no |
| B — Oracle → PostgreSQL migration (RQ2) | probe selection after evolution, Tables 7, 8, 10, Fig. 5 | `bash docs/study_b/run_study_b_offline.sh` (levels 1–2) | no |
| B — testbed re-measurement | re-deploys 1,802 units and re-collects telemetry | `bash docs/study_b/run_study_b_testbed.sh` (level 3) | PostgreSQL 17 |

## Quick start (macOS/Linux, Python 3.14 used for verification; 3.12+ should work)

```bash
git clone https://github.com/vasyllyashkevych/eam-reproducibility.git && cd eam-reproducibility
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
bash run_all.sh                         # Studies A, C, ablation, LOFO, figures, 145 number checks, tests (about 20 s on the verification machine)
bash docs/study_b/run_study_b_offline.sh     # Study B from the migration corpus (about 30 min on the verification machine, no database)
```

`run_all.sh` ends with the line `checks 145  PASS 145  FAIL 0` and `13 passed`; the full comparison table is
`docs/results/reproduction_summary.md`. A value outside its tolerance is reported as FAIL and the script exits with a non-zero status.

## Supplementary analysis: Study A — leave-one-drift-dimension-out (LOFO)

`code/study_a_lofo.py` tests how much each of the nine drift dimensions contributes to **evolution-state classification macro-F1**
under the controlled Study A scenario. It does **not** re-estimate Study B monitoring coverage (PCRw), MRSR or runtime defect
recall, and it does not change any other result.

```bash
python3 code/study_a_lofo.py       # about 3 s; writes docs/results/study_a_lofo/, docs/figures/fig5a_study_a_lofo_radar.png and docs/figures/fig5b_study_a_lofo_paired_ci.png
```

Each dimension is masked in turn, the EDI weights are renormalised over the remaining dimensions, that dimension is excluded
from `CriticalCheck`, and the five-state classifier thresholds are recalibrated on training seeds **101–110**. The method is
evaluated on **40 paired seeds (1–40)**; the output has the mean macro-F1 drop and a 95% paired bootstrap interval
(15,000 resamples, deterministic seeds). The all-dimensions control reproduces the Study A C0 macro-F1 of **0.9683**.

* `docs/results/study_a_lofo/StudyA_leave_one_dimension_out.csv` — summary by dimension.
* `docs/results/study_a_lofo/StudyA_LOFO_paired_runs.csv` — paired 40-seed results.
* `docs/figures/fig5a_study_a_lofo_radar.png`, `docs/figures/fig5b_study_a_lofo_paired_ci.png` — the two panels of Fig. 5 (separate files).
* `docs/STUDY_A_LOFO.md` — protocol, interpretation and limitations.

This is a supplementary sensitivity analysis: the measured loss depends on the Study A scenario, the dimensions, the threshold
recalibration and the critical-override rule. It is not a causal attribution and not a general ranking across domains.
