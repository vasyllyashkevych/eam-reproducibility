# Reproducibility package — PAPER021433 (IJITCS)

**Paper:** *Evolution-Aware Monitoring for Evolving Information Systems: Multidimensional Drift Assessment with a Version-Dependent Reference Model*
**Manuscript version:** PAPER021433 Final (revision submitted November 2026)
**Artifact version:** 1.0.0, prepared 16 November 2026
**Corresponding author:** Vasyl Lyashkevych, Ivan Franko National University of Lviv — vasyl.liashkevych@lnu.edu.ua

## 1. What this package reproduces

| Study | Question | Status in this package |
|---|---|---|
| A — controlled drift injection (RQ1) | Can a nine-dimensional drift vector classify the evolution state? | **Fully reproducible** from code (synthetic generator, fixed seeds). |
| Joint ablation (RQ1, RQ2) | What do the release-change and runtime profiles add together? | **Fully reproducible** from code. |
| C — security drift of five libraries (RQ3) | Do advisories reveal exposure changes that code monitoring misses? | **Reproducible offline** from the frozen OSV cache and exported snapshot data. |
| B — Oracle-to-PostgreSQL migration and PostgreSQL 17 testbed (RQ2) | Which probes stay valid after a migration? | **Reproducible from the corpus** with `docs/study_b/run_study_b_offline.sh` (levels 1–2, no database; recorded testbed measurements in `data/study_b/recorded/`). The testbed itself can be rebuilt with `docs/study_b/run_study_b_testbed.sh` (level 3, PostgreSQL 17); its timing-dependent telemetry is not expected to repeat exactly. Step-by-step: `TUTORIAL.md`. |

The insufficient-evidence state of Equation (11) is part of the operational rule; it was **not** evaluated as an outcome in Study A.

## 5. Data, denominators and temporal cuts

* **Study A** is generated by `code/multidrift_eval.py` and `code/controlled_drift.py`: nine AR(1) series (α = 0.85, μ = 0.10, σ = 0.015), 120 steps, injection plan and five benchmark phases in `data/study_a/injection_plan_and_seeds.json`. Training seeds 101–110, test seeds 1–40, bootstrap seed 0, 100 Dirichlet weight draws (seed 0).
* **Joint ablation:** the same 40 test runs with an approved release at step 25 (role and goal +0.25, W = 8, Δrel = 0.25/0.40 = 0.625); 36 properties, nine secondary links; runtime trigger 0.35, re-armed below 0.175; defect seeds 1001–1040 (uniform) and 2001–2040 (change-coupled); paired across variants. A score that stays above the threshold does not trigger a rebuild at every step (`tests/test_algorithm_triggers.py`).
* **Study C:** five libraries × 50 repository snapshots = 250 snapshots; 5 × 49 = **245 consecutive transitions** (not 250); 454 releases. Versions at each snapshot were resolved with `git describe --tags --abbrev=0` and exported to `data/study_c/snapshots_manifest.csv`; release tags and dates to `release_tags.csv`; code-drift values and the static/EWMA alerts to `code_drift_snapshots.csv` and `monitoring_alerts.csv`. OSV responses are frozen in `osv_cache.json` (captured 5 November 2026). All "now"-dependent horizons are evaluated at the fixed instant **2026-11-05 23:40** (`code/paths.py`, `EAM_OSV_AS_OF`). Aliases are merged (earliest publication date, highest CVSS v3.1 base score); unscored advisories count as 5.5. The pinned-release shares use only releases whose horizon has elapsed at the evaluation instant (421, 411 and 351 releases at 1, 2 and 5 years).
* **Study B:** the migration corpus `data/study_b/ds/O2P_GOLDEN_TESTSET_v03_full.csv` (1,802 units, 1,060 from a production database), the analysis code (`docs/study_b/e2e/`), the testbed code (`docs/study_b/ops/src/`), the measurements recorded on the testbed (`data/study_b/recorded/`: 15 platform checks, COMMIT probes, instrumented routine runs, execution errors, deployment results, probe counts and the telemetry of all ten runs) and the author's original outputs (`data/study_b/reference/`). `data/study_b_public/` keeps the per-run metric files for the quick path through `run_all.sh`. Table 7 is the deterministic re-run produced by level 1.

## 6. Mapping numbers to files

`docs/RESULTS_TRACEABILITY.csv` lists every number of the paper (150 rows: 145 checked by `code/check_expected.py`, 5 visual) with its manuscript location, output file, producing script and command. `docs/expected/expected_results.json` stores the printed values and tolerances; `code/check_expected.py` recomputes the 145 automatically checked values from the regenerated outputs (no constants) and writes `docs/results/reproduction_summary.md` with expected, obtained, difference, tolerance, PASS/FAIL and source.

## 7. Expected outputs and tolerances

Tolerance is half a unit of the last printed digit (for example ±0.0005 for 0.968); counts must match exactly. Study A, the ablation and Study C are deterministic. On the verification machine the regenerated Study A and ablation CSV files were byte-identical to the author's original outputs; the Study C summary was identical except for p-values that differed in the 15th–16th significant digit, which does not affect any printed value. If a value falls outside its tolerance, `check_expected.py` reports FAIL and exits with status 1; do not edit expected values by hand.

## 8. Known limitations

* Level 3 of Study B (re-running the testbed) was not repeated during this verification; levels 1–2 were, and their outputs were identical to the original ones (`docs/study_b/logs/study_b_comparison.json`).
* The first, non-deterministic corpus-experiment run that gave an earlier version of Table 7 differed from the published deterministic re-run by at most 0.008 in F1.
* `run_all.ps1` was not executed on Windows.

## 9. Troubleshooting

* `KeyError ... missing from the frozen OSV cache` — the cache file was altered; restore it or run `EAM_ONLINE=1 python3 security_cvss.py` (results may then change because OSV records change over time).
* `boundary_real.py` needs the unit tables produced by Study B level 1 (`bash docs/study_b/run_study_b_offline.sh`); `run_all.sh` skips it with a message until they exist. To read them from another place set `EAM_STUDY_B_DIR`.
* Fonts: Fig. 4 and the Study B/C figures request Times New Roman, Fig. 5a/5b use the matplotlib default font; other fonts change the appearance, not the data.
